## Environment issues found and fixed during setup (real, not hypothetical)
1. mongo-spark-connector 10.4.0 (initial guess) works, but 10.7.0 is the latest version
   confirmed compatible with Spark 3.2-3.5 + Mongo 4.2+ (mongodb.com/docs/spark-connector/v10.x) —
   v11.x requires Spark 4.0+, which pyspark==3.5.7 does not satisfy.
2. `ModuleNotFoundError: numpy` on first pyspark.ml import — added numpy to requirements.
3. `ModuleNotFoundError: distutils` on first pyspark.ml import (Python 3.12 removed it from
   stdlib; pyspark 3.5.x's pyspark/ml/image.py still imports it) — added setuptools>=80,
   which vendors a working `import distutils` shim.
4. Host port 8000 was already bound by another local dev tool (Laragon PHP dev server on
   127.0.0.1:8000) — moved the API's host-mapped port to 8088 in docker-compose.yml.
5. Kafka's host-mapped listener (localhost:9094) is intermittently flaky under Docker
   Desktop/WSL2 on Windows (TCP connects fine, but the Kafka wire-protocol handshake
   occasionally gets dropped) — the actual pipeline always uses the internal listener
   (kafka:9092), which was tested repeatedly with zero failures.
