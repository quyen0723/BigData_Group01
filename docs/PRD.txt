MovieLens Hybrid Recommendation System - PRD & System Design Specification

1. Tóm tắt điều hành
MovieLens Hybrid Recommendation System là một nền tảng recommendation có khả năng mở rộng,
chuyển dữ liệu rating lịch sử và các rating events mới thành danh sách Top-N movie
recommendations được cá nhân hóa. Thiết kế chủ động tách Data Ingestion, Offline
Analytics/Modeling, Online Serving độ trễ thấp và Periodic Model Refresh để từng concern có thể mở
rộng, kiểm thử và thay đổi độc lập.
Trải nghiệm recommendation thay đổi theo lượng thông tin mà hệ thống đang có về user:


0 history: trả về Popularity Top-N an toàn, ổn định và có minimum support.



Few history: khai thác Content-Based từ các movie user đã rating tốt; có thể optional fusion với
Popularity để giảm rủi ro do history còn thưa.



Enough history: dùng ALS Collaborative Filtering làm nguồn personalization chính; có thể bổ sung
content similarity khi cần.

Điểm trọng tâm của project không phải "chạy ALS trên MovieLens", mà là xây dựng một end-to-end Big Data
system có data lifecycle, model lifecycle, serving lifecycle, feedback loop, validation và performance evidence
rõ ràng.

2. Tổng quan sản phẩm cho khách hàng
2.1 Hệ thống giải quyết vấn đề gì?
Một movie catalog lớn tạo ra discovery problem: user không thể tự xem xét toàn bộ nội dung, trong
khi một danh sách "most popular" duy nhất bỏ qua sở thích cá nhân. Hệ thống giảm search cost bằng
cách chọn và xếp hạng một tập movie nhỏ, có liên quan hơn với từng user.

2.2 User nhận được gì?


Personalized Top-N recommendations cho user có đủ rating history.



Fallback recommendations hữu ích cho new user hoặc user có rất ít history.



Content-aware suggestions dựa trên similarity với các movie user đã thích.



Recommendation response loại bỏ movie user đã rating khi latest history có sẵn.



Serving vẫn hoạt động bằng current model version trong lúc candidate model mới được train và
validate.

2.3 Vì sao đây là Big Data system?
Project không được xem là Big Data chỉ vì dataset có hàng chục triệu ratings. Big Data evidence nằm ở
distributed processing, các joins/aggregations tạo shuffle, scalable model training, batch + streaming
ingestion, storage optimization và controlled performance experiments. Kiến trúc cho phép tăng
partitions/executors khi workload tăng thay vì phải thiết kế lại toàn bộ pipeline.

3. Mục tiêu, Non-goals và Success Criteria
3.1 Goals


Xây dựng reproducible end-to-end pipeline từ raw MovieLens đến Analytics, Recommendation,
Serving và Feedback.



Cung cấp personalized recommendation với cold-start handling rõ ràng.



Minh chứng distributed data engineering bằng PySpark, Parquet, Spark SQL và một MapReduce
workload có ý nghĩa.



Đánh giá recommendation bằng cả prediction metrics và ranking metrics.



Cung cấp system-performance evidence bằng ít nhất một controlled experiment.



Dùng MongoDB làm low-latency serving store và có write/read-back evidence.



Thiết kế streaming path để rating mới cập nhật serving state và sau đó ảnh hưởng periodic
retraining.

3.2 Non-goals


Xây dựng Netflix clone ở production scale hoặc full movie-streaming platform.



Suy luận age, gender, location hay demographics không tồn tại trong MovieLens 32M.



Retrain ALS sau từng rating event.



Dùng BERT/GPT chỉ để tăng độ mới khi core data modality là user-item-rating interaction.



Cam kết content-safety filtering nếu chưa có user age/parental setting và movie certification từ
nguồn đáng tin cậy.

4. User Journeys và Functional Capabilities
4.1 Journey A - user chưa có usable history
1. Request: User gọi Recommendation API.
2. History check: API đọc interaction_count / User History từ MongoDB serving state.

3. Strategy: nếu history = 0, router chọn Popularity Top-N.
4. Filtering: áp dụng latest-history exclusion và optional policy filter nếu đủ dữ liệu.
5. Response: trả Top-N ngay mà không invoke ALS training.

4.2 Journey B - user có few ratings
6. Profile: dùng latest User History để xác định các movie được rating tích cực.
7. Content candidates: lấy Precomputed Similar-Movie Lists cho các movie này.
8. Optional fusion: có thể merge với Popularity để ổn định sparse-history recommendation.
9. Re-rank: Exclude Already-Rated và thực hiện Lightweight Re-rank.
10. Response: trả Top-N.

4.3 Journey C - user có enough history
11. Primary source: đọc Precomputed ALS Top-N.
12. Optional complement: có thể thêm content candidates để cải thiện diversity hoặc sparse areas.
13. Re-rank: áp dụng latest-history exclusion và optional policy constraints.
14. Response: trả Top-N mà không chạy Spark training trong request path.

7. System Architecture
Kiến trúc tách rõ data preparation, offline intelligence, online response và model lifecycle. Core data
flows dùng đường liền; policy/eligibility filtering chỉ là extension nếu chưa có external
age/certification data.

7.1 Layer 1 - Data Ingestion & Curated Storage
Historical MovieLens files được xử lý bằng PySpark Batch ETL. Rating events mới đi qua Kafka và
Spark Structured Streaming, được lưu vào Raw Event Storage, sau đó Validate / Transform trước khi
append vào Curated Parquet. Event đã validate cũng cập nhật online User History / interaction_count
trong MongoDB.

7.2 Layer 2A - Offline Analytics & Modeling
Curated data cấp dữ liệu độc lập cho MapReduce Statistics, Spark SQL Analytics và Recommendation
Modeling. Recommendation không phải workload duy nhất; việc tách này giúp traceability với
BDA501 và làm rõ trách nhiệm của từng subsystem.

7.3 Layer 2B - Online Serving
Recommendation request không retrain ALS. Request path chỉ đọc User History, chọn một hoặc nhiều
serving sources đã chuẩn bị sẵn, Exclude Already-Rated, optional Policy/Fusion và trả Top-N.

7.4 Layer 3 - Feedback & Periodic Model Refresh
Accumulated curated data kích hoạt Scheduled Retraining. Candidate Model Version phải đi qua
Validation / Promotion Gate trước khi Regenerate Serving Artifacts và Publish / Activate. Current
version tiếp tục serve đến khi promotion thành công.

9.4 Popularity Baseline và Fallback
Popularity vừa là Top-N baseline, vừa là serving strategy cho 0-history users. Để tránh movie chỉ có
một rating cao bất thường, cần minimum support và/hoặc weighted score thay vì chỉ sort raw average
rating.

10. Online Serving
20. Request: client gọi Recommendation API với userId.
21. State lookup: API đọc User History / interaction_count từ MongoDB.
22. Route: chọn 0 / Few / Enough history.
23. Retrieve: đọc Popularity Top-N, Precomputed Similar-Movie Lists hoặc Precomputed ALS Top-N.
24. Fresh-history exclusion: loại item user vừa rating nhưng chưa kịp phản ánh trong ALS artifacts.
25. Optional policy / fusion: chỉ áp dụng khi đủ source data và strategy yêu cầu.
26. Lightweight Re-rank: merge/rank nhẹ, không chạy Spark training.
27. Response: trả Top-N kèm strategy, modelVersion và generatedAt.
